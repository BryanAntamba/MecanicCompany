2. Metodología de Prueba

2.1 Herramienta Utilizada

Se utilizó OWASP React Vulnerability Scanner, una herramienta de análisis estático (SAST) que identifica patrones potencialmente inseguros en código JavaScript/TypeScript mediante búsqueda de palabras clave y análisis de estructura.

2.2 Alcance del Análisis

  • Backend TypeScript (Express.js + Prisma ORM)
  • Frontend React Native (Expo Router)
  • Configuración de variables de entorno (.env)
  • Manejo de credenciales y tokens JWT
  • Comunicación HTTP/HTTPS

2.3 Categorías OWASP Analizadas

  • A02:2021 – Cryptographic Failures: Uso de HTTP inseguro
  • A02:2021 – Secrets: Credenciales hardcodeadas o expuestas

4. Prácticas de Seguridad Implementadas

✅ Gestión de Secretos: Todas las credenciales sensibles están en archivo .env, no hardcodeadas en código fuente.

4.1 Variables de Entorno Protegidas

  • JWT_SECRET: Clave privada para firmar tokens JWT. Almacenada en .env
  • MAIL_USER/MAIL_PASS: Credenciales SMTP de correo. No expuestas en código
  • DATABASE_URL: String de conexión PostgreSQL. Protegido en .env
  • MAIL_HOST, MAIL_PORT, MAIL_FROM: Configuración de correo. Variables de entorno

4.2 Gestión de Tokens

  • Tokens JWT con expiración de 8 horas
  • Token guardado en AsyncStorage del cliente (no localStorage vulnerable)
  • Header Authorization: Bearer {token} en peticiones autenticadas
  • Middleware de validación en rutas protegidas

4.3 Comunicación API

  • Validación de credenciales en backend (bcryptjs para hashing de contraseñas)
  • Timeout de 10 segundos en solicitudes HTTP
  • Manejo de errores seguro (no expone detalles internos del servidor)
  • Content-Type: application/json en todas las peticiones

4.4 Validación y Autenticación

  • AuthMiddleware verifica presencia y validez de token en rutas autenticadas
  • soloAdmin middleware valida rol de administrador
  • Códigos de verificación con expiración de 15 minutos
  • Contraseñas hasheadas con bcryptjs (10 rounds)

6. Mitigaciones Implementadas

6.1 Gestión de Credenciales

✅ Implementado: Archivo .env con todas las variables sensibles
  • JWT_SECRET: "mecaniccompany_jwt_secret_2026"
  • MAIL_USER y MAIL_PASS: Almacenados en .env, no en código
  • DATABASE_URL: Conexión PostgreSQL segura en .env

6.2 Autenticación

✅ Implementado: JWT con expiración y validación
  • Tokens con expiración de 8 horas
  • Middleware de verificación en rutas protegidas
  • Validación de rol (admin vs mecánico)

6.3 Envío de Correos Seguro

✅ Implementado: Gestión segura de credenciales SMTP
  • MAIL_USER y MAIL_PASS en variables de entorno
  • Error handling si las variables no están configuradas
  • Templates HTML seguros con validación de entrada

6.4 Producción

Para ambiente de producción, se recomienda:

  • Implementar HTTPS con certificado SSL/TLS válido
  • Re-habilitar rate limiting en auth.routes.ts
  • Usar variables de entorno en hosting (AWS Secrets Manager, Azure Key Vault, etc.)
  • Configurar CORS apropiadamente para dominios autorizados

Veredicto Final: La aplicación está lista para uso en ambiente de desarrollo. Para producción, se deben implementar las recomendaciones mencionadas arriba, especialmente HTTPS y rate limiting.
