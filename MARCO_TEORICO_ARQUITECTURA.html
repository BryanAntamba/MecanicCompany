1. Introducción

El presente documento estructura de manera jerárquica los términos técnicos, arquitectura, lenguajes de programación, entornos y APIs utilizados en el desarrollo del sistema MecanicCompany. La organización responde a una clasificación de términos grandes con sus respectivos subtérminos, ordenados por relevancia e importancia en la estructura tecnológica del proyecto.

2. Términos y Conceptos Fundamentales

2.1 Arquitectura de Software

La arquitectura de software del sistema MecanicCompany se fundamenta en un modelo de tres capas distribuidas que separa las responsabilidades entre presentación, lógica de negocio y persistencia de datos.

2.1.1 Arquitectura de Tres Capas (Three-Tier Architecture)

  • Capa de Presentación (Frontend). Responsable de la interacción directa con el usuario final. Implementada mediante React Native con soporte multiplataforma (web, Android, iOS).
  • Capa de Lógica de Negocio (Backend). Procesa las solicitudes del cliente, implementa reglas de negocio y coordina operaciones. Desarrollada con Node.js y Express.js.
  • Capa de Persistencia (Base de Datos). Almacena y recupera datos mediante un gestor de base de datos relacional PostgreSQL con intermediación del ORM Prisma.

2.1.2 Patrón de Arquitectura Cliente-Servidor

  • Cliente. Aplicación frontend que realiza peticiones HTTP hacia el servidor backend.
  • Servidor. API REST que procesa solicitudes, ejecuta operaciones y devuelve respuestas en formato JSON.
  • Comunicación. Protocolo HTTP/HTTPS con autenticación mediante tokens JWT (JSON Web Tokens).

2.1.3 Patrones de Diseño Implementados

  • Patrón MVC (Model-View-Controller). Aplicado en el backend para la organización de controladores, modelos y rutas.
  • Patrón Singleton. Utilizado en la configuración de conexiones a base de datos y variables de entorno.
  • Patrón Repository. Implementado mediante Prisma Client para abstraer operaciones de base de datos.
  • Patrón Middleware. Empleado en Express.js para validación, autenticación y manejo de errores.

2.2 Stack de Tecnologías

El stack tecnológico de MecanicCompany está conformado por un conjunto integrado de herramientas, frameworks y librerías que trabajan en conjunto para proporcionar una solución completa de software.

2.2.1 Tecnologías Frontend

  • React Native (v0.81.5). Framework de desarrollo multiplataforma que permite crear aplicaciones para iOS, Android y web desde una única base de código.
  • Expo (v54.0.8). Plataforma de desarrollo y distribución que simplifica el proceso de compilación y deployment de aplicaciones React Native.
  • Expo Router (v6.0.23). Sistema de enrutamiento basado en archivos para manejar navegación entre pantallas de la aplicación.
  • React Navigation (v7.1.8). Librería de navegación nativa que gestiona la pila de pantallas, tabs y drawers.
  • TypeScript. Lenguaje tipado que extiende JavaScript proporcionando verificación de tipos estática en tiempo de compilación.

2.2.2 Tecnologías Backend

  • Node.js. Entorno de ejecución de JavaScript en servidor que permite ejecutar código JavaScript del lado del servidor.
  • Express.js (v4.19.2). Framework minimalista y flexible para construir APIs REST en Node.js.
  • TypeScript. Proporciona tipado estático al código backend para mejorar la calidad y mantenibilidad.
  • Prisma (v5.14.0). ORM (Object-Relational Mapping) que abstrae operaciones de base de datos y proporciona un cliente tipado.

2.2.3 Tecnologías de Base de Datos

  • PostgreSQL. Sistema gestor de base de datos relacional de código abierto con soporte para tipos de datos complejos y transacciones ACID.
  • Prisma Client. Cliente de base de datos generado automáticamente que proporciona métodos tipados para consultas SQL.

2.3 Lenguajes de Programación

El sistema MecanicCompany utiliza lenguajes de programación modernos y tipados que facilitan la detección de errores y mejoran la mantenibilidad del código.

2.3.1 JavaScript (ECMAScript 2020 o superior)

  • Uso en Frontend. Lenguaje base de React Native para la lógica de componentes y manejo de estado.
  • Uso en Backend. A través de Node.js, permite ejecutar código JavaScript en servidor.
  • Características. Dinámicamente tipado, orientado a prototipos, soporte para programación asincrónica mediante Promises y async/await.

2.3.2 TypeScript (v5.4.5)

  • Descripción. Superset de JavaScript que añade tipado estático opcional, interfaces, clases y decoradores.
  • Modo Estricto. Configuración tsconfig.json con modo estricto habilitado ("strict": true) para máxima verificación de tipos.
  • Compilación. Se transpila a JavaScript antes de la ejecución o interpretación.
  • Ventajas. Detección de errores en tiempo de compilación, mejor autocompletado en IDEs, documentación mediante tipos.

2.3.3 SQL (Structured Query Language)

  • Uso. Lenguaje declarativo para definir esquema de base de datos y ejecutar consultas en PostgreSQL.
  • Abstracción mediante Prisma. Las consultas SQL se generan automáticamente desde el cliente de Prisma, evitando escritura manual de SQL.

2.4 Frameworks y Librerías

Los frameworks y librerías son componentes reutilizables que proporcionan funcionalidades predefinidas para acelerar el desarrollo y mejorar la consistencia del código.

2.4.1 Frameworks Principales

  • React Native. Framework de componentes declarativos que abstrae diferencias entre plataformas (iOS, Android, Web).
  • Express.js. Framework web minimalista que proporciona enrutamiento, middleware y soporte para aplicaciones API.
  • Expo. Framework que envuelve React Native proporcionando herramientas de desarrollo, compilación y distribución.

2.4.2 Librerías de Utilidad y Seguridad

  • jsonwebtoken (v9.0.2). Genera y valida tokens JWT para autenticación stateless en API REST.
  • bcryptjs (v2.4.3). Librería para hashing y verificación de contraseñas con algoritmo bcrypt.
  • helmet (v8.2.0). Middleware que configura headers HTTP de seguridad para proteger contra vulnerabilidades comunes.
  • cors (v2.8.5). Middleware para habilitar Cross-Origin Resource Sharing entre cliente y servidor.
  • express-rate-limit (v8.5.2). Middleware para limitación de tasa de solicitudes y prevención de ataques DoS.

2.4.3 Librerías de Validación y Transformación de Datos

  • zod (v3.23.8). Librería de validación de datos que proporciona esquemas tipados y mensajes de error descriptivos.
  • dotenv (v16.4.5). Carga variables de entorno desde archivo .env en tiempo de ejecución.

2.4.4 Librerías de Navegación y Enrutamiento

  • expo-router (v6.0.23). Sistema de enrutamiento basado en convención de directorios (file-based routing).
  • React Navigation (v7.1.8). Proporciona componentes de navegación (NavigationContainer, BottomTabNavigator, etc.).
  • @react-navigation/bottom-tabs (v7.4.0). Componente especializado para navegación mediante tabs en la parte inferior.

2.4.5 Librerías de Almacenamiento y Gestión de Archivos

  • @react-native-async-storage/async-storage (v2.2.0). Base de datos local key-value para almacenamiento persistente en cliente.
  • expo-file-system (v19.0.22). Acceso a sistema de archivos del dispositivo para lectura y escritura.
  • expo-image-picker (v17.0.11). Permite seleccionar imágenes desde galería o cámara del dispositivo.

2.4.6 Librerías de Comunicación y Datos

  • nodemailer (v6.9.13). Librería para envío de correos electrónicos desde el servidor backend.
  • multer (v2.1.1). Middleware para Node.js que maneja carga de archivos multipart/form-data.
  • expo-av (v16.0.8). Proporciona capacidades de audio y video en aplicaciones Expo.

2.5 Base de Datos

El subsistema de persistencia de datos utiliza una arquitectura relacional con abstracción mediante ORM para garantizar integridad referencial y eficiencia en operaciones.

2.5.1 Sistema Gestor de Base de Datos

  • PostgreSQL. Base de datos relacional de código abierto con características avanzadas como índices B-tree, tipos de datos personalizados y soporte para transacciones ACID.
  • Ubicación. Servidor local en localhost:5432 con base de datos nombrada "mecaniccompany".
  • Autenticación. Credenciales configuradas en variables de entorno para acceso seguro.

2.5.2 Mapeo Objeto-Relacional (ORM)

  • Prisma (v5.14.0). ORM moderna que proporciona abstracción de base de datos mediante lenguaje de esquema propio (Prisma Schema).
  • Características. Generación automática de tipos TypeScript, migraciones de esquema, seeds para datos de prueba, Prisma Studio para visualización de datos.
  • Prisma Client. Cliente tipado que reemplaza queries SQL manuales con métodos JavaScript/TypeScript seguros.

2.5.3 Estructura de Datos Principal

  • Modelos Principales. Solicitud, Mantenimiento, Producto, Finanza, Usuario, Cliente, Mecánico.
  • Relaciones. Relaciones uno-a-muchos (1:N) entre Solicitud y Mantenimiento, muchos-a-muchos (N:M) entre Productos y Mantenimientos.
  • Tipos de Datos. String, Int, DateTime, Decimal (para precios y costos), Boolean, JSON (para datos complejos como repuestos utilizados).

2.5.4 Operaciones de Base de Datos

  • Operaciones CRUD. Create (Crear), Read (Leer), Update (Actualizar), Delete (Eliminar) implementadas mediante métodos de Prisma Client.
  • Transacciones. Soporte para operaciones multipasos que garantizan integridad de datos mediante rollback en caso de error.
  • Migraciones. Cambios de esquema versionados mediante Prisma Migrate que permiten evolucionar estructura sin pérdida de datos.

2.6 Interfaces de Programación de Aplicaciones (APIs)

Las APIs definen contratos entre cliente y servidor que especifican qué operaciones pueden ejecutarse, qué datos se transmiten y qué respuestas se esperan.

2.6.1 Arquitectura de API REST

  • Definición. REST (Representational State Transfer) es estilo arquitectónico que utiliza métodos HTTP estándar (GET, POST, PUT, DELETE) para operaciones sobre recursos.
  • Recursos. Cada recurso es identificado por URL única (ej. /api/productos, /api/solicitudes).
  • Formato de Datos. JSON (JavaScript Object Notation) como formato de serialización para solicitudes y respuestas.

2.6.2 Protocolos de Comunicación

  • HTTP/HTTPS. Protocolo de transferencia de hipertexto con soporte para conexiones seguras (HTTPS con TLS).
  • Métodos HTTP. GET (lectura), POST (creación), PUT (actualización), DELETE (eliminación), PATCH (actualización parcial).
  • Códigos de Estado. 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.

2.6.3 Autenticación y Autorización

  • JSON Web Tokens (JWT). Tokens autofirmados que contienen información de usuario codificada en formato base64, utilizados en header Authorization: Bearer [token].
  • Middleware de Autenticación. Valida presencia y validez de token JWT en cada solicitud a endpoints protegidos.
  • Roles y Permisos. Control de acceso basado en roles (RBAC) que determina operaciones permitidas según tipo de usuario (admin, mecánico, cliente).

2.6.4 Endpoints de API Principales

  • Productos. GET /api/productos (listar), POST /api/productos (crear), PUT /api/productos/:id (actualizar), DELETE /api/productos/:id (eliminar).
  • Solicitudes. GET /api/solicitudes (listar), POST /api/solicitudes (crear), PUT /api/solicitudes/:id (actualizar), DELETE /api/solicitudes/:id (eliminar).
  • Mantenimientos. GET /api/mantenimientos (listar), POST /api/mantenimientos (crear), PUT /api/mantenimientos/:id (actualizar), DELETE /api/mantenimientos/:id (eliminar).
  • Finanzas. GET /api/finanzas (listar), POST /api/finanzas (crear), PUT /api/finanzas/:id (actualizar), GET /api/finanzas/:id/detalles (obtener detalles).
  • Autenticación. POST /api/auth/login (iniciar sesión), POST /api/auth/register (registrarse), POST /api/auth/logout (cerrar sesión).

2.6.5 Validación de Datos en API

  • Validación de Entrada. Esquemas Zod que verifican tipo, formato y restricciones de datos antes de procesar solicitud.
  • Mensajes de Error. Respuestas detalladas que especifican qué campos fallaron validación y por qué.
  • Transformación de Datos. Conversión automática de tipos (ej. string a número, ISO 8601 a Date).

2.6.6 Limitación de Tasa y Seguridad

  • Rate Limiting. Middleware express-rate-limit que limita número de solicitudes por IP para prevenir ataques de fuerza bruta.
  • CORS (Cross-Origin Resource Sharing). Configuración que especifica qué dominios pueden acceder a API desde navegadores.
  • Headers de Seguridad. Helmet middleware que configura Content-Security-Policy, X-Frame-Options, X-Content-Type-Options y otros headers protectores.

2.7 Entornos de Desarrollo y Ejecución

Los entornos de desarrollo proporcionan herramientas, configuraciones y runtimes necesarios para ejecutar, probar y desplegar la aplicación.

2.7.1 Entorno de Desarrollo Local

  • Sistema Operativo. Windows con PowerShell y Node.js instalado.
  • Gestor de Paquetes. npm (Node Package Manager) versión 9 o superior para instalar dependencias.
  • Editor de Código. Visual Studio Code con extensiones para TypeScript, React Native y Prisma.

2.7.2 Runtime de Ejecución

  • Node.js. Entorno de ejecución basado en motor V8 que permite ejecutar JavaScript en servidor.
  • Versión Mínima. Node.js 18.x o superior con soporte para módulos ES6 y async/await.
  • npm. Gestor de paquetes que descarga e instala dependencias declaradas en package.json.

2.7.3 Herramientas de Compilación y Transpilación

  • TypeScript Compiler (tsc). Transpila código TypeScript a JavaScript compatible con versiones antiguas de Node.js.
  • ts-node-dev. Herramienta de desarrollo que compila TypeScript sobre la marcha y reinicia servidor automáticamente al detectar cambios (hot reload).
  • Babel. Transpilador JavaScript que en Expo convierte código moderno a compatible con navegadores y plataformas antiguas.

2.7.4 Servidor de Desarrollo Backend

  • Express Development Server. Servidor HTTP local en puerto 3000 o configurable mediante variable de entorno PORT.
  • Ejecución. Iniciado mediante comando "npm run dev" que ejecuta ts-node-dev sobre archivo src/server.ts.
  • Características. Soporte para middleware, enrutamiento dinámico y CORS para comunicación con frontend.

2.7.5 Servidor de Desarrollo Frontend

  • Expo Development Server. Servidor local que compila y sirve aplicación React Native.
  • Plataformas Objetivo. Web (mediante navegador en localhost:19006), Android (mediante emulador), iOS (mediante simulador).
  • Ejecución. Iniciado mediante comando "npm run web" (web), "npm run android" (Android), "npm run ios" (iOS).
  • Hot Reload. Recompilación automática y recarga en cliente al detectar cambios en código.

2.7.6 Gestor de Base de Datos de Desarrollo

  • PostgreSQL Local. Servidor PostgreSQL ejecutándose en localhost:5432 accesible desde aplicación mediante connection string en variable de entorno DATABASE_URL.
  • Prisma Studio. Interfaz gráfica web ejecutada mediante "npm run db:studio" que permite visualizar, crear, editar y eliminar registros sin escribir SQL.
  • Migraciones. Ejecutadas mediante "npm run db:migrate" que aplica cambios de esquema a base de datos.

2.7.7 Configuración de Variables de Entorno

  • Archivo .env. Archivo no versionado que contiene configuraciones sensibles como DATABASE_URL, JWT_SECRET, PORT, API_BASE_URL.
  • dotenv. Librería que carga variables de archivo .env al process.env de Node.js en tiempo de ejecución.
  • Seguridad. Variables sensibles nunca se commitean a repositorio git, se asignan en plataforma de deployment.

2.7.8 Dependencias de Proyecto (package.json)

  • Backend: 18 dependencias principales. Express, Prisma, jsonwebtoken, bcryptjs, cors, helmet, zod, multer, nodemailer, express-rate-limit y otras.
  • Backend: 8 dependencias de desarrollo. TypeScript, ts-node-dev, Prisma CLI, @types/* para tipado.
  • Frontend: 44 dependencias principales. React, React Native, Expo, React Navigation, TypeScript, AsyncStorage, Date Picker, Icon Libraries.
  • Versionamiento Semántico. Dependencias especificadas con caret (^) para permitir actualizaciones menores y parches.

3. Conclusión

El sistema MecanicCompany se fundamenta en una arquitectura moderna, escalable y mantenible que integra tecnologías de punta en desarrollo web y móvil. La estructura de tres capas separa claramente responsabilidades, facilitando desarrollo paralelo, testing independiente y mantenimiento futuro. El uso de TypeScript en frontend y backend proporciona verificación de tipos estática que reduce bugs en producción. El stack tecnológico seleccionado (React Native, Express, PostgreSQL con Prisma) representa estándares industriales con excelente documentación, comunidad activa y ecosistema maduro de herramientas complementarias. La arquitectura REST con JWT para autenticación, combinada con middleware de seguridad (Helmet, CORS, Rate Limiting), implementa mejores prácticas de seguridad de aplicaciones web modernas.
