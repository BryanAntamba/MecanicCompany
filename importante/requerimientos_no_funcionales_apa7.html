1. Introducción

Los requerimientos no funcionales definen las características de calidad, rendimiento, seguridad y usabilidad que debe cumplir el sistema MecanicCompany. Estos requerimientos establecen los estándares de excelencia operativa y garantizan que la plataforma sea confiable, segura y fácil de usar para todos los usuarios: clientes, mecánicos, personal de inventario, personal financiero y administradores.

El presente documento enumera treinta requerimientos no funcionales organizados por categoría, detallando su descripción, componentes afectados y nivel de prioridad en la implementación del sistema.

2. Requerimientos No Funcionales

2.1 Rendimiento y Velocidad

RNF-001. Tiempo de respuesta rápido
El sistema debe responder a las acciones del usuario en menos de 2 segundos para operaciones normales como búsquedas, filtros y cargas de datos.
Componente: Frontend y Backend
Prioridad: Alta
RNF-002. Contraseñas encriptadas
Todas las contraseñas deben almacenarse protegidas usando encriptación bcrypt, nunca en texto plano.
Componente: Backend
Prioridad: Alta
RNF-003. Acceso por roles
El sistema debe mostrar diferentes funciones según el tipo de usuario: Cliente, Mecánico, Inventario, Financiero o Administrador.
Componente: Frontend y Backend
Prioridad: Alta
RNF-004. Validación de correos corporativos
Solo permitir acceso si el correo coincide con el dominio correcto: clientes @gmail.com, mecánicos @mecanic.com, inventario @inventariomecanic.com, financiero @finanzasmecanic.com.
Componente: Frontend y Backend
Prioridad: Alta
RNF-005. Recuperación de contraseña segura
Enviar código de seis dígitos que expira en quince minutos y solo se usa una vez, bloqueando la cuenta después de cinco intentos fallidos.
Componente: Backend
Prioridad: Alta
RNF-006. Sesiones con límite de duración
Los permisos de acceso deben expirar después de veinticuatro horas de inactividad, obligando al usuario a iniciar sesión nuevamente.
Componente: Backend
Prioridad: Alta

2.2 Seguridad y Protección de Datos

RNF-007. Fotos y documentos en la nube
Las fotos de vehículos, reportes y perfiles deben almacenarse de forma segura en la base de datos como archivos codificados.
Componente: Backend
Prioridad: Media
RNF-008. Reportes automáticos por correo
Enviar reportes técnicos de mantenimiento con fotos, costos y detalles al correo del cliente de forma automática.
Componente: Backend
Prioridad: Alta
RNF-009. Confirmación antes de acciones críticas
Pedir confirmación mediante modal antes de eliminar usuarios, enviar reportes, registrar pagos o cambiar el estado de solicitudes.
Componente: Frontend
Prioridad: Media
RNF-010. Validación de formularios en tiempo real
Mostrar mensajes de error debajo de cada campo del formulario mientras el usuario escribe, sin esperar a enviar.
Componente: Frontend
Prioridad: Alta
RNF-011. Base de datos organizada
La base de datos debe tener búsquedas rápidas en correos, placas, productos y fechas mediante índices que optimicen el desempeño.
Componente: Backend
Prioridad: Media
RNF-012. Protección contra ataques
Sanitizar y validar todas las entradas del usuario para prevenir inyección de código maligno en SQL, JavaScript y otros lenguajes.
Componente: Backend
Prioridad: Alta
RNF-013. Información segura en sesión
Los tokens de acceso deben guardarse de forma segura en el dispositivo, en memoria en la web, sin exponerse en mensajes de error.
Componente: Frontend
Prioridad: Alta
RNF-014. Bloqueo de capturas en móvil
En dispositivos móviles, prohibir que los empleados mecánico, inventario, financiero y administrador tomen capturas de pantalla de información sensible.
Componente: Frontend
Prioridad: Media
RNF-015. Conexión segura en producción
En la versión final para usuarios reales, forzar conexión HTTPS con certificados válidos y rechazar conexiones HTTP sin protección.
Componente: Backend
Prioridad: Alta

2.3 Usabilidad e Interfaz

RNF-016. Estructura consistente de carpetas
Organizar el código en carpetas claras para pantallas, componentes, estilos, validaciones y utilidades.
Componente: Frontend y Backend
Prioridad: Media
RNF-017. Documentación en el código
Cada archivo debe incluir comentarios explicando qué hace y para qué sirven las funciones principales.
Componente: Frontend y Backend
Prioridad: Media
RNF-018. Navegación personalizada
No mostrar la barra de navegación nativa del sistema operativo. Crear barras propias personalizadas que se adapten a cada rol de usuario.
Componente: Frontend
Prioridad: Media
RNF-019. Mensajes de error claros
Los errores deben ser específicos y útiles, como "El correo no existe" en lugar de "Error en el servidor".
Componente: Frontend y Backend
Prioridad: Alta
RNF-020. Variables de configuración seguras
Guardar datos sensibles como contraseñas de correo y URLs del servidor en archivos ocultos de configuración, nunca en el código visible.
Componente: Backend
Prioridad: Alta

2.4 Confiabilidad y Disponibilidad

RNF-021. Historial de auditoría
Registrar cuándo se crean, editan o eliminan solicitudes, usuarios y pagos para investigar problemas y auditar la actividad del sistema.
Componente: Backend
Prioridad: Baja
RNF-022. Sincronización de datos
Si el usuario pierde conexión a internet, la aplicación debe permitir funciones offline básicas y sincronizar los cambios cuando regrese la conexión.
Componente: Frontend
Prioridad: Baja
RNF-023. Tamaño de archivos controlado
Las fotos y documentos no deben exceder límites de tamaño para no saturar el servidor ni ralentizar la descarga en dispositivos móviles.
Componente: Frontend y Backend
Prioridad: Media
RNF-024. Respuestas consistentes
Las respuestas del servidor siempre deben seguir el mismo formato JavaScript Object Notation con estructuras predecibles.
Componente: Backend
Prioridad: Media
RNF-025. Manejo de zonas horarias
El sistema debe entender correctamente fechas y horas en cualquier zona geográfica donde se use, convirtiendo automáticamente al horario local.
Componente: Backend
Prioridad: Baja

2.5 Mantenibilidad y Escalabilidad

RNF-026. Accesibilidad de la aplicación
La interfaz debe ser accesible para usuarios con discapacidades visuales o motoras, permitiendo navegación con teclado y compatibilidad con lectores de pantalla.
Componente: Frontend
Prioridad: Media
RNF-027. Compatibilidad multi-plataforma
El sistema debe funcionar correctamente en dispositivos móviles con sistemas operativos Android e iOS, y en navegadores web modernos en computadoras.
Componente: Frontend
Prioridad: Alta
RNF-028. Escalabilidad del sistema
La arquitectura debe permitir crecer el número de usuarios, solicitudes y datos sin degradar significativamente el rendimiento del sistema.
Componente: Backend
Prioridad: Alta
RNF-029. Copias de seguridad automáticas
El sistema debe realizar copias de seguridad automáticas de la base de datos al menos una vez al día, permitiendo recuperar datos en caso de pérdida.
Componente: Backend
Prioridad: Media
RNF-030. Monitoreo y alertas de errores
El sistema debe monitorear continuamente el rendimiento y enviar alertas automáticas cuando ocurran errores críticos o caídas del servicio.
Componente: Backend
Prioridad: Media
