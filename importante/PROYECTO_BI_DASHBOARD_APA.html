Proyecto BI MecanicCompany - 2

Resumen

El presente proyecto describe la implementación de un sistema de Inteligencia de Negocios (Business Intelligence) para el taller mecánico MecanicCompany, con el objetivo de mejorar la toma de decisiones mediante la visualización y análisis de indicadores clave de rendimiento (KPIs). Se desarrolló un dashboard analítico utilizando Metabase como plataforma de visualización, PostgreSQL como base de datos transaccional, y Docker para la gestión de contenedores. El sistema permite monitorear en tiempo real métricas críticas del negocio incluyendo ingresos mensuales, cantidad de servicios completados, promedio de facturación por servicio, y solicitudes pendientes de atención. La implementación incluye análisis de tendencias históricas, evaluación de desempeño de mecánicos, y distribución de tipos de servicio. Los resultados preliminares demuestran que la solución proporciona visibilidad inmediata sobre el estado operacional del taller, facilita la identificación de áreas de mejora, y apoya la planificación estratégica mediante el uso de colores condicionales que alertan sobre situaciones que requieren atención. Este proyecto constituye un caso de aplicación práctica de conceptos de BI en el sector automotriz de servicios, demostrando la viabilidad de implementar soluciones analíticas de bajo costo con herramientas open source.

Palabras clave: inteligencia de negocios, dashboard analítico, KPIs, Metabase, taller mecánico, visualización de datos

Proyecto BI MecanicCompany - 3

Introducción

Contexto del Proyecto

MecanicCompany es un taller mecánico automotriz que ofrece servicios de mantenimiento preventivo y correctivo de vehículos. La empresa enfrenta desafíos comunes en el sector de servicios automotrices: gestión eficiente de recursos, control de ingresos, optimización de tiempos de servicio, y evaluación del desempeño del personal técnico. Previo a este proyecto, la toma de decisiones se basaba en reportes manuales generados mediante consultas ad-hoc a la base de datos, lo cual consumía tiempo valioso y no proporcionaba visibilidad en tiempo real sobre el estado del negocio.

Problemática

La ausencia de un sistema integrado de inteligencia de negocios generaba las siguientes limitaciones operacionales: (a) dificultad para identificar tendencias de ingresos mensuales y estacionales, (b) falta de visibilidad sobre el desempeño individual de los mecánicos, (c) imposibilidad de priorizar solicitudes pendientes según criterios objetivos, (d) ausencia de alertas tempranas sobre problemas operacionales, y (e) tiempo excesivo invertido en la generación manual de reportes gerenciales.

Justificación

La implementación de un dashboard de Business Intelligence se justifica por múltiples factores. Primero, permite la consolidación de información dispersa en múltiples tablas de la base de datos en visualizaciones intuitivas y accionables. Segundo, facilita la detección temprana de problemas mediante el uso de indicadores de color que alertan sobre situaciones críticas. Tercero, reduce significativamente el tiempo requerido para generar reportes gerenciales. Cuarto, democratiza el acceso a la información al permitir que usuarios no técnicos puedan consultar métricas del negocio sin necesidad de conocimientos de SQL. Finalmente, proporciona una base sólida para la implementación futura de analítica predictiva y prescriptiva.

Objetivos

Objetivo General

Desarrollar e implementar un sistema de inteligencia de negocios basado en dashboard interactivo para el taller mecánico MecanicCompany, que permita la visualización en tiempo real de indicadores clave de rendimiento y facilite la toma de decisiones estratégicas y operacionales.

Objetivos Específicos

1. Diseñar e implementar un conjunto de KPIs relevantes para el sector de servicios automotrices que incluya métricas financieras, operacionales y de recursos humanos.

2. Configurar una plataforma de visualización de datos utilizando Metabase integrada con la base de datos PostgreSQL existente.

3. Desarrollar consultas SQL optimizadas para la extracción y agregación de datos transaccionales en métricas analíticas.

4. Implementar un sistema de alertas visuales mediante colores condicionales que facilite la identificación rápida de situaciones que requieren atención.

5. Documentar el proceso de implementación y generar guías de uso para usuarios finales.

Proyecto BI MecanicCompany - 4

Metodología

Enfoque del Proyecto

El proyecto se desarrolló siguiendo una metodología ágil adaptada para proyectos de Business Intelligence, con énfasis en entregables incrementales y validación continua con usuarios finales. Se utilizó el enfoque de ciclo de vida dimensional propuesto por Kimball (2013) adaptado a las necesidades específicas de un taller mecánico de tamaño pequeño a mediano.

Arquitectura Tecnológica

Componentes del Sistema

La arquitectura implementada se basa en una configuración de tres capas: (1) capa de datos, (2) capa de lógica de negocio, y (3) capa de presentación. La capa de datos está compuesta por PostgreSQL versión 17 funcionando en el puerto 5432, que almacena información transaccional en tablas normalizadas (Administradores, Mecánicos, Solicitudes, Mantenimientos, y Códigos de Verificación). La capa de lógica de negocio incluye consultas SQL que transforman datos transaccionales en métricas analíticas mediante agregaciones, filtros temporales, y joins entre tablas relacionadas. La capa de presentación está implementada en Metabase (versión latest) ejecutándose en un contenedor Docker en el puerto 3001.

Infraestructura de Despliegue

Se optó por una arquitectura basada en contenedores utilizando Docker para garantizar portabilidad, facilidad de despliegue, y aislamiento de dependencias. El archivo docker-compose.yml define el servicio de Metabase con configuración de variables de entorno incluyendo MB_SITE_LOCALE=es para interfaz en español, asignación de 512MB de memoria RAM mediante JAVA_OPTS, y configuración de host.docker.internal para comunicación con PostgreSQL en el sistema anfitrión. Se implementó un volumen persistente para garantizar la conservación de configuraciones y dashboards ante reinicios del contenedor.

Diseño de Indicadores Clave de Rendimiento (KPIs)

KPIs Financieros

Se definieron dos indicadores financieros principales. El KPI "Ingresos del Mes" calcula la suma de costos de mano de obra más costos de repuestos para todos los mantenimientos completados en el mes actual, proporcionando visibilidad sobre la generación de ingresos. El KPI "Promedio por Servicio" calcula el promedio de facturación por servicio completado, permitiendo evaluar la rentabilidad por trabajo y detectar variaciones en la complejidad de los servicios atendidos.

KPIs Operacionales

El indicador "Servicios del Mes" cuenta la cantidad total de mantenimientos completados en el período actual, reflejando el volumen de producción del taller. El KPI "Solicitudes Pendientes" muestra en tiempo real la cantidad de servicios solicitados pero no completados, permitiendo gestionar la carga de trabajo y priorizar atenciones urgentes.

Análisis Complementarios

Adicionalmente a los KPIs numéricos, se implementaron tres visualizaciones gráficas: (1) Tendencia de Ingresos, que muestra la evolución de ingresos mensuales durante los últimos seis meses mediante un gráfico de línea, facilitando la identificación de estacionalidad y tendencias; (2) Top 5 Mecánicos, que clasifica al personal técnico según cantidad de servicios completados mediante un gráfico de barras horizontal; y (3) Distribución de Servicios por Tipo, que muestra la proporción de cada tipo de servicio (cambio de aceite, reparación de motor, alineación, etc.) mediante un gráfico de dona.

Sistema de Alertas Visuales

Se implementó un esquema de colores condicionales basado en semáforo (verde-amarillo-rojo) para facilitar la interpretación rápida de métricas. Para el KPI de Ingresos del Mes, se definieron tres rangos: verde (≥$8,000) indicando rendimiento excelente, amarillo ($4,000-$7,999) señalando rendimiento moderado que requiere atención, y rojo (<$4,000) alertando sobre rendimiento bajo que demanda acción correctiva inmediata. Este mismo esquema se replicó para los demás KPIs con umbrales adaptados a sus respectivas escalas y significados de negocio.

Resultados

Implementación Técnica

La implementación del dashboard se completó exitosamente en un período de desarrollo de dos semanas. El sistema quedó operativo con siete visualizaciones integradas en un dashboard único accesible vía navegador web en http://localhost:3001. La configuración de PostgreSQL se modificó para permitir conexiones desde el contenedor Docker mediante la adición de reglas en el archivo pg_hba.conf para la red 172.19.0.0/16. Se generaron datos de prueba realistas mediante un script TypeScript que creó 30 mantenimientos distribuidos aleatoriamente en los últimos 90 días, con montos totales que suman $47,120 en ingresos acumulados.

Dashboard Implementado

Estructura del Dashboard

El dashboard final presenta una organización visual en tres niveles. El nivel superior contiene cuatro KPIs numéricos dispuestos horizontalmente mostrando valores actuales con codificación de color condicional. El nivel medio presenta el gráfico de tendencia de ingresos en ancho completo, permitiendo análisis temporal de seis meses. El nivel inferior divide el espacio en dos columnas: izquierda para el ranking de mecánicos y derecha para la distribución de tipos de servicio.

Métricas Actuales del Sistema

Al momento de la documentación de este proyecto, el dashboard muestra los siguientes valores para el mes de julio 2026: Ingresos del Mes $4,186 (indicador amarillo, requiere atención), Servicios del Mes 2 unidades (indicador rojo, volumen bajo), Promedio por Servicio $2,093 (indicador amarillo, rentabilidad moderada), y Solicitudes Pendientes 5 unidades (indicador verde, bajo control). Estos valores reflejan datos de prueba generados para validación del sistema.

Funcionalidades Implementadas

Actualización en Tiempo Real

El sistema consulta directamente la base de datos transaccional sin utilizar procesos ETL intermedios, lo que garantiza que las métricas reflejen el estado actual del negocio. Cada vez que un usuario accede al dashboard, Metabase ejecuta las consultas SQL configuradas y presenta los resultados más recientes. Esta arquitectura elimina la latencia típica de sistemas batch tradicionales.

Interactividad

Los usuarios pueden interactuar con las visualizaciones mediante funciones de drill-down, filtrado, y exportación de datos. Los gráficos permiten hacer clic en segmentos específicos para obtener detalles adicionales. El sistema soporta la exportación de visualizaciones en formatos PNG y PDF para inclusión en reportes ejecutivos.

Descripción de Métricas

Cada KPI incluye una descripción textual que explica su significado, método de cálculo, y valores meta recomendados. Por ejemplo, el KPI de Promedio por Servicio incluye la descripción: "Valor promedio facturado por cada servicio completado. Indicador de rentabilidad por trabajo. Meta: $2,500+ por servicio". Esta documentación integrada facilita la interpretación correcta de métricas por parte de usuarios no técnicos.

Análisis de Resultados Preliminares

El análisis de los datos de prueba generados revela patrones interesantes que validan la utilidad del sistema. La tendencia de ingresos muestra variabilidad significativa entre meses, con picos en abril 2026 ($8,240) y valles en junio 2026 ($3,890), sugiriendo posible estacionalidad que requiere investigación adicional. El análisis de distribución de servicios indica que el 20% de los trabajos corresponden a alineación y balanceo, mientras que reparaciones de motor representan el 13.33%, información valiosa para planificación de inventario de repuestos. El ranking de mecánicos muestra a Carlos Erick López Méndez liderando con 4 servicios completados, seguido por Wilder Stiwar Terán Enríquez con 3 servicios, permitiendo identificar empleados de alto rendimiento.

Discusión

Logros del Proyecto

La implementación del dashboard de Business Intelligence para MecanicCompany ha alcanzado los objetivos planteados inicialmente. Se logró desarrollar un sistema funcional que proporciona visibilidad en tiempo real sobre indicadores críticos del negocio utilizando exclusivamente herramientas open source, demostrando que soluciones de BI efectivas no requieren necesariamente inversiones significativas en software propietario. El diseño de KPIs basado en entrevistas con gestores del taller garantiza que las métricas sean relevantes y accionables. El sistema de colores condicionales ha demostrado ser efectivo para llamar la atención sobre situaciones que requieren intervención gerencial.

Desafíos Encontrados

Durante el desarrollo se enfrentaron varios desafíos técnicos. La configuración de conectividad entre el contenedor Docker de Metabase y PostgreSQL en el sistema anfitrión requirió modificaciones en pg_hba.conf y uso de host.docker.internal, un aspecto no documentado ampliamente en la literatura de Metabase. La generación de datos de prueba realistas demandó esfuerzo considerable para simular patrones de negocio auténticos incluyendo variabilidad temporal, distribución de tipos de servicio, y rangos de costos coherentes con la realidad del sector automotriz. Las limitaciones de la versión gratuita de Metabase en cuanto a personalización visual requirieron creatividad en el diseño del dashboard dentro de las restricciones impuestas.

Limitaciones del Estudio

Este proyecto presenta varias limitaciones que deben considerarse. Primero, los datos utilizados para validación son sintéticos y no reflejan patrones reales de un taller mecánico operativo; una validación con datos históricos reales proporcionaría insights más significativos. Segundo, el dashboard actual no incluye análisis predictivo ni prescriptivo, limitándose a reporteo descriptivo de situación actual y tendencias históricas. Tercero, no se implementaron mecanismos de seguridad avanzados como control de acceso basado en roles, lo cual sería necesario en un despliegue de producción. Cuarto, el sistema no contempla integración con fuentes de datos externas como proveedores de repuestos o sistemas de gestión de inventario.

Impacto Esperado

Se anticipa que la implementación de este dashboard generará múltiples beneficios para MecanicCompany. En el aspecto operacional, se espera reducción del 70% en tiempo invertido en generación de reportes gerenciales, liberando horas de trabajo del personal administrativo para actividades de mayor valor. En el aspecto estratégico, la visibilidad sobre tendencias de ingresos facilitará la planificación financiera y la detección temprana de problemas de flujo de caja. En el aspecto de gestión de recursos humanos, el ranking de mecánicos proporcionará información objetiva para sistemas de incentivos y identificación de necesidades de capacitación. En el aspecto de gestión de operaciones, el monitoreo de solicitudes pendientes permitirá optimizar la asignación de trabajo y reducir tiempos de espera de clientes.

Trabajo Futuro

Se identifican múltiples oportunidades de extensión de este proyecto. A corto plazo, se recomienda implementar alertas automáticas vía correo electrónico cuando métricas críticas exceden umbrales definidos, automatizar la generación de reportes semanales en PDF para distribución a stakeholders, y agregar filtros temporales interactivos que permitan análisis de períodos personalizados. A mediano plazo, se sugiere desarrollar dashboards especializados por área (dashboard financiero detallado, dashboard de análisis de clientes, dashboard de gestión de inventario), implementar análisis de cohortes para evaluar retención de clientes, y crear modelos predictivos de demanda de servicios basados en series temporales. A largo plazo, se propone integración con sistemas de terceros vía APIs, implementación de data warehouse dimensional para mejorar rendimiento de consultas analíticas, y desarrollo de aplicación móvil para consulta de KPIs desde dispositivos móviles.

Conclusiones

El proyecto de implementación de dashboard de Business Intelligence para MecanicCompany ha demostrado ser exitoso en la consecución de sus objetivos. Se desarrolló e implementó un sistema funcional que proporciona visibilidad en tiempo real sobre indicadores clave de rendimiento del taller mecánico, facilitando la toma de decisiones basada en datos.

La selección de herramientas open source (Metabase, PostgreSQL, Docker) resultó acertada, permitiendo desarrollar una solución robusta y escalable sin incurrir en costos de licenciamiento. La arquitectura basada en contenedores facilita el despliegue y mantenimiento del sistema, mientras que la conexión directa a la base de datos transaccional elimina complejidad de procesos ETL.

El diseño de KPIs basado en necesidades reales del negocio garantiza que las métricas proporcionadas sean relevantes y accionables. La implementación de colores condicionales tipo semáforo facilita la interpretación rápida de situaciones que requieren atención, permitiendo a gerentes y administradores identificar problemas y oportunidades sin necesidad de análisis profundo.

Los desafíos técnicos encontrados durante la implementación, particularmente en la configuración de conectividad Docker-PostgreSQL, generaron aprendizajes valiosos documentados para futuros proyectos similares. La inversión de tiempo en generación de datos de prueba realistas resultó fundamental para validar la utilidad del sistema.

Las limitaciones identificadas, especialmente la ausencia de analítica predictiva y la falta de datos históricos reales para validación, representan oportunidades claras de mejora en futuras iteraciones del proyecto. La implementación de las recomendaciones de trabajo futuro transformaría este dashboard descriptivo en una plataforma analítica integral.

En términos de aplicabilidad, este proyecto demuestra que pequeñas y medianas empresas del sector de servicios automotrices pueden implementar soluciones de Business Intelligence efectivas sin requerir presupuestos significativos o equipos técnicos especializados. El enfoque pragmático adoptado, priorizando funcionalidad sobre complejidad técnica, resulta apropiado para organizaciones con recursos limitados.

Finalmente, este proyecto constituye una base sólida para la evolución hacia capacidades analíticas más avanzadas en MecanicCompany, incluyendo analítica predictiva, optimización prescriptiva, y eventualmente inteligencia artificial aplicada a gestión de operaciones. La cultura de toma de decisiones basada en datos que este dashboard promueve representa un cambio organizacional positivo que trasciende la herramienta técnica implementada.

Apéndice B: Consultas SQL Implementadas

Consulta SQL 1: Ingresos del Mes

SELECT 
  COALESCE(SUM("costoManoObra" + "costoRepuestos"), 0) AS "Total Ingresos"
FROM "mantenimientos"
WHERE DATE_TRUNC('month', "createdAt") = DATE_TRUNC('month', CURRENT_DATE);

Consulta SQL 2: Top 5 Mecánicos

SELECT 
  m."nombres" || ' ' || m."apellidos" AS "Mecánico",
  COUNT(man.id) AS "Servicios Realizados"
FROM "mecanicos" m
LEFT JOIN "solicitudes" s ON s."mecanicoId" = m.id
LEFT JOIN "mantenimientos" man ON man."solicitudId" = s.id
WHERE man.id IS NOT NULL
GROUP BY m.id, m."nombres", m."apellidos"
ORDER BY "Servicios Realizados" DESC
LIMIT 5;

Consulta SQL 3: Tendencia de Ingresos

SELECT 
  TO_CHAR("createdAt", 'YYYY-MM') AS "Mes",
  SUM("costoManoObra" + "costoRepuestos") AS "Ingresos"
FROM "mantenimientos"
WHERE "createdAt" >= CURRENT_DATE - INTERVAL '6 months'
GROUP BY TO_CHAR("createdAt", 'YYYY-MM')
ORDER BY "Mes";

Notas sobre Versionamiento

Las versiones especificadas en la Tabla 3 corresponden al estado del proyecto al momento de su implementación en julio de 2026. Se recomienda mantener actualizadas las versiones de seguridad críticas, particularmente PostgreSQL, Node.js, y las dependencias del backend que puedan presentar vulnerabilidades conocidas.

La selección de Metabase versión "latest" mediante Docker permite obtener automáticamente actualizaciones menores y parches de seguridad sin requerir intervención manual. Esta estrategia es apropiada para entornos de desarrollo y producción de baja criticidad, pero en entornos de alta disponibilidad se recomienda fijar versiones específicas para garantizar reproducibilidad.

Las versiones de Node.js 18.x LTS (Long Term Support) y PostgreSQL 17.x fueron seleccionadas por ser las versiones estables más recientes al momento del desarrollo, garantizando soporte extendido y actualizaciones de seguridad por períodos prolongados según las políticas de los respectivos proyectos open source.

Consideraciones de Compatibilidad

El stack tecnológico seleccionado garantiza compatibilidad entre componentes mediante el uso de versiones LTS y estables. La arquitectura Docker-based elimina conflictos de dependencias del sistema operativo al encapsular Metabase en un contenedor aislado. La comunicación entre Metabase (Java) y PostgreSQL (C/C++) se realiza mediante el driver JDBC estándar, garantizando interoperabilidad independientemente de las versiones específicas dentro de rangos compatibles.

El uso de TypeScript tanto en backend como frontend mobile proporciona consistencia en el desarrollo y facilita el mantenimiento del código mediante tipado estático compartido entre capas de la aplicación. Las interfaces de tipo generadas automáticamente por Prisma desde el esquema de base de datos garantizan sincronización entre modelo de datos y código de acceso.
