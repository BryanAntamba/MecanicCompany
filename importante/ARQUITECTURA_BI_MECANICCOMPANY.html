1. Fuentes de Datos (Data Sources)

1.1 Base de Datos Operacional

El sistema utiliza PostgreSQL como motor de base de datos relacional, gestionado mediante Prisma ORM. Las tablas principales incluyen:

  • Tabla Solicitudes: registro de peticiones de servicio
  • Tabla Mantenimientos: servicios completados
  • Tabla Mecánicos: personal técnico y especialidades
  • Tabla Clientes: información de usuarios del servicio
  • Tabla Administradores: gestión del sistema

Tecnologías: PostgreSQL, Prisma ORM

1.2 Datos Transaccionales

La información de operación diaria capturada por el sistema incluye:

  • Estados de solicitudes (Pendiente, En_proceso, Completado)
  • Tiempos de servicio (fecha inicio y finalización)
  • Costos de mano de obra
  • Costos de repuestos
  • Asignaciones de mecánicos a servicios

1.3 Datos de Comunicación

El sistema de emails y notificaciones genera datos de:

  • Reportes enviados a clientes
  • Confirmaciones de citas
  • Notificaciones de cambio de estado
  • Logs de comunicación SMTP

Tecnología: Nodemailer

1.4 Datos de Usuarios

Información de acceso y actividad del sistema:

  • Sesiones JWT con duración de 8 horas
  • Roles de usuario: Administrador, Mecánico, Cliente
  • Estados laborales de mecánicos
  • Disponibilidad en tiempo real
  • Especialidades técnicas del personal

Tecnología: JSON Web Tokens (JWT) para autenticación

2. Procesos ETL/ELT (Extract, Transform, Load)

2.1 Extracción (Extract)

Las consultas desde PostgreSQL se realizan mediante:

  • Extracción incremental diaria de datos operacionales
  • Consultas estructuradas con Prisma ORM
  • Filtros por rangos de fechas y estados de servicios
  • Operaciones JOIN entre tablas relacionadas
  • Captura de datos históricos para análisis temporal

Tecnologías: Prisma Queries, TypeScript

2.2 Transformación (Transform)

El procesamiento y cálculo de métricas incluye:

  • Cálculo de tiempos de servicio (diferencia entre fecha inicio y fin)
  • Agregación de costos totales (mano de obra + repuestos)
  • Conversión de estados categóricos a métricas numéricas
  • Identificación de tendencias mediante análisis temporal
  • Clasificación de servicios por categorías
  • Cálculo de KPIs de productividad por mecánico

Tecnologías: Node.js, lógica de negocio en TypeScript

2.3 Carga (Load)

La inserción en el Data Warehouse se realiza mediante:

  • Carga batch nocturna programada
  • Actualización de tablas dimensionales
  • Inserción de nuevos hechos (mantenimientos, solicitudes)
  • Validación de integridad referencial
  • Registro de auditoría de procesos ETL

Tecnologías: Scheduled Jobs, Cron

2.4 Limpieza de Datos

Los procesos de calidad y validación incluyen:

  • Eliminación de registros duplicados
  • Normalización de campos de texto
  • Validación de formatos (fechas, correos, teléfonos)
  • Manejo de valores nulos y missing data
  • Estandarización de formatos de fecha y hora

3. Data Warehouse (Almacén de Datos)

3.1 Tablas Dimensionales

Las dimensiones del negocio incluyen:

  • Dim_Tiempo: fechas, días de la semana, meses, trimestres, años
  • Dim_Mecanico: ID, nombre completo, especialidad, años de experiencia, estado laboral
  • Dim_Cliente: ID, nombre, información de contacto, historial de servicios
  • Dim_Vehiculo: marca, modelo, año de fabricación, tipo de vehículo
  • Dim_TipoServicio: categorías de mantenimiento (frenos, motor, transmisión, etc.)
  • Dim_Estado: estados del ciclo de vida (Pendiente, En_proceso, Completado)

3.2 Tablas de Hechos

Los eventos medibles del negocio se almacenan en:

  • Fact_Mantenimientos: servicios completados, costos totales, tiempos de ejecución
  • Fact_Solicitudes: peticiones recibidas, estados actuales, asignaciones a mecánicos
  • Fact_Ingresos: ventas diarias, ingresos por mecánico, ingresos por tipo de servicio
  • Fact_Productividad: métricas de eficiencia de mecánicos, tiempos promedio

Modelo de datos: Star Schema (Esquema Estrella), Snowflake Schema

3.3 Modelo Relacional

El esquema estrella (Star Schema) implementado incluye:

  • Tabla central de hechos con métricas cuantitativas
  • Dimensiones conectadas mediante claves foráneas
  • Claves foráneas optimizadas para consultas OLAP
  • Índices en columnas de filtrado frecuente
  • Agregaciones pre-calculadas para reportes comunes

3.4 Optimización

Estrategias de performance y escalabilidad:

  • Índices B-tree en columnas clave de búsqueda
  • Particionamiento de tablas por fecha (mensual, anual)
  • Vistas materializadas para consultas frecuentes
  • Compresión de datos históricos mayores a 1 año
  • Caché de consultas mediante Redis o similar

Tecnología: PostgreSQL Data Warehouse

4. Análisis y Visualización (Analytics & Reporting)

4.1 Dashboard de Productividad

Los KPIs de operación incluyen:

  • Número de solicitudes atendidas por mecánico
  • Tiempo promedio de servicio por tipo de mantenimiento
  • Tasa de conversión (solicitudes recibidas vs. completadas)
  • Utilización de capacidad instalada del taller
  • Eficiencia por especialidad técnica

Métricas clave: Reducción del 70% en tiempo de registro; precisión de datos del 98%.

4.2 Análisis de Demanda

Tendencias y patrones identificados:

  • Top 10 de servicios más solicitados
  • Marcas y modelos de vehículos más atendidos
  • Horarios pico de demanda de servicios
  • Estacionalidad de tipos de mantenimiento
  • Predicción de demanda futura mediante series temporales

4.3 Dashboard Financiero

Análisis de rentabilidad del negocio:

  • Ingresos totales (desagregados por día, semana, mes)
  • Margen de contribución: mano de obra vs. repuestos
  • Ticket promedio por servicio
  • Ingresos generados por mecánico
  • Rentabilidad por tipo de servicio
  • Proyección de ingresos basada en tendencias históricas

Resultados esperados: Incremento del 25% en capacidad de atención; aumento del 30% en clientes recurrentes.

4.4 Análisis de Clientes

Customer Intelligence aplicado:

  • Segmentación de clientes por tipo de vehículo
  • Frecuencia de visitas y patrones de retorno
  • Valor de vida del cliente (LTV - Lifetime Value)
  • Patrones de mantenimiento preventivo vs. correctivo
  • Tasa de retención y análisis de churn
  • Net Promoter Score (NPS) para medir satisfacción

4.5 Reportes Estratégicos

Decisiones basadas en datos mediante:

  • Reporte mensual ejecutivo para dirección
  • Análisis de competitividad en el mercado
  • Optimización de inventario de repuestos
  • Planificación de personal según demanda
  • Identificación de oportunidades de mejora

4.6 Herramientas de Visualización

Tecnologías recomendadas para la capa de presentación:

  • Power BI de Microsoft
  • Tableau para análisis visual avanzado
  • Metabase como solución open-source
  • Chart.js para gráficos web interactivos
  • React Charts para integración con frontend
  • D3.js para visualizaciones personalizadas

Funcionalidades incluyen: dashboards interactivos en tiempo real, reportes exportables en PDF y Excel, y alertas automáticas de KPIs críticos.
