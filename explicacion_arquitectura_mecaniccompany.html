Arquitectura del Sistema MecanicCompany

1. Introducción a la Arquitectura

El sistema MecanicCompany implementa una arquitectura de tres capas (Three-Tier Architecture) con una capa adicional de servicios externos. Esta arquitectura es robusta, escalable y sigue los mejores estándares de desarrollo de aplicaciones empresariales. La separación en capas permite que cada componente pueda desarrollarse, probarse y mantenerse de forma independiente, facilitando la evolución futura del sistema.

2. Descripción de Capas

Capa de Presentación (Frontend)

La capa de presentación es la interfaz a través de la cual los usuarios interactúan con el sistema. MecanicCompany utiliza React Native con Expo versión 54.0.8, escrito en TypeScript 5.4.5, lo que permite crear una aplicación que funciona tanto en dispositivos móviles (iOS y Android) como en navegadores web.

Los componentes principales de esta capa incluyen: (a) Rutas y Navegación, implementadas con expo-router versión 6.23 para manejo eficiente de pantallas; (b) Manejo de Estado, utilizando React Navigation 7.1.8 para gestionar la pila de navegación; y (c) Almacenamiento Local, con AsyncStorage para dispositivos móviles y sessionStorage para navegadores web, permitiendo que los usuarios mantengan su sesión activa.

Esta capa es responsable de validar datos en el lado del cliente, mostrar errores amigables y proporcionar una experiencia de usuario optimizada. La comunicación entre el frontend y el backend se realiza mediante peticiones HTTP REST.

Capa de Lógica de Negocios (Backend)

El backend de MecanicCompany es un servidor Node.js construido con Express versión 4.19.2, también desarrollado en TypeScript 5.4.5. Este servidor implementa toda la lógica empresarial del sistema y expone una API REST que el frontend consume.

Los componentes principales de esta capa incluyen autenticación y seguridad. La implementación de JWT (JSON Web Tokens) proporciona autenticación stateless, mientras que la validación de credenciales utiliza contraseñas hasheadas mediante bcrypt con salt de 12 iteraciones. Un middleware de autenticación verifica cada petición entrante para asegurar que el usuario esté autorizado.

Los controladores por dominio manejan diferentes áreas funcionales del sistema. El Controlador de Solicitudes gestiona la creación, lectura y actualización de solicitudes de mantenimiento. El Controlador de Mantenimientos registra trabajos realizados, fotos y costos. El Controlador de Inventario maneja productos y niveles de stock. El Controlador de Finanzas administra facturas y pagos. Finalmente, el Controlador de Administración gestiona usuarios y configuración del sistema.

Los servicios internos complementan la funcionalidad. El Servicio de Validación verifica que los datos cumplan reglas de negocio. El Servicio de Email proporciona integración con Nodemailer OAuth para enviar correos electrónicos automáticos. El Servicio de Auditoría registra todas las operaciones críticas para cumplimiento normativo. El Servicio de Almacenamiento de Fotos gestiona imágenes en formato base64.

Capa de Persistencia (Base de Datos)

La persistencia de datos se logra mediante PostgreSQL, una base de datos relacional robusta y confiable, alojada localmente en el puerto 5432. El acceso a la base de datos se realiza a través de Prisma versión 5.14.0, un ORM (Object-Relational Mapping) moderno que proporciona type safety y una interfaz fluida para trabajar con datos.

La estructura de datos principal incluye múltiples entidades. Los Usuarios abarcan Clientes, Mecánicos, Personal de Inventario, Personal Financiero y Administradores, cada uno con roles y permisos específicos. Las Solicitudes son registros de solicitudes de mantenimiento con estado (Pendiente, En Proceso, Completado, Rechazado). Los Mantenimientos contienen detalles técnicos de los trabajos realizados, incluyendo diagnóstico y acciones tomadas. Los Productos constituyen un catálogo de repuestos y componentes disponibles. El Inventario registra niveles de stock y movimientos de entrada y salida. Las Finanzas incluyen facturas, pagos registrados e información de cuentas por cobrar. La Auditoría mantiene un registro histórico de todas las operaciones del sistema.

Las características de almacenamiento incluyen almacenamiento de fotografías en formato base64 dentro de campos TEXT, lo que permite su inclusión directa en reportes PDF. Los índices de base de datos, pendientes de implementación, serán necesarios en campos de búsqueda frecuente como correos, placas de vehículos y SKU de productos. Las relaciones están bien definidas entre tablas para mantener integridad referencial.

Capa de Servicios Externos

Aunque no es una capa tradicional, el sistema depende de servicios externos que complementan su funcionalidad. El Servicio de Email utiliza Nodemailer con autenticación OAuth para enviar correos automatizados con reportes, facturas y notificaciones. La Criptografía implementa bcrypt versión 12 para el hashing seguro de contraseñas de forma irreversible. Los Tokens de Seguridad utilizan JWT con expiración configurada (actualmente 28800 segundos o 8 horas, pero requiere actualización a 86400 segundos o 24 horas según especificación).

3. Flujo de Comunicación

Un flujo típico en MecanicCompany funciona como sigue. En primer lugar, el usuario (cualquier actor) abre la aplicación móvil o web. Luego, realiza autenticación cuando el frontend envía credenciales (email y contraseña) al backend. El backend autentica las credenciales contra la base de datos y genera un JWT. Durante la sesión activa, el frontend almacena el token localmente y lo incluye en todas las peticiones posteriores. El usuario realiza una acción, por ejemplo, solicitar mantenimiento.

El backend valida que la acción sea permitida según el rol del usuario. Se ejecuta la lógica de negocio correspondiente. Los datos se guardan en PostgreSQL mediante Prisma. La operación realizada se registra en la auditoría. Se envía un correo electrónico si es necesario mediante Nodemailer. Finalmente, el frontend recibe una respuesta REST y actualiza la interfaz de usuario.

4. Seguridad

La arquitectura implementa múltiples capas de seguridad. La Autenticación se realiza mediante JWT con expiración temporal. La Autorización valida roles en cada endpoint. La Encriptación protege las contraseñas hasheadas con bcrypt. La Validación asegura que todos los datos ingresados se validen antes de procesarlos. La Auditoría mantiene un registro completo de operaciones para detectar anomalías. El Aislamiento garantiza que cada usuario solo vea sus propios datos según su rol.

5. Ventajas de Esta Arquitectura

La arquitectura de tres capas presenta varias ventajas significativas. La Escalabilidad permite que cada capa crezca independientemente. La Mantenibilidad asegura que cambios en una capa no afecten las otras. La Testabilidad permite que cada componente se pruebe aisladamente. El Rendimiento se optimiza gracias a la separación de responsabilidades. La Reusabilidad permite que componentes y servicios se reutilicen en diferentes contextos. La Seguridad se fortalece con múltiples niveles de validación y autenticación.

7. Conclusión

La arquitectura de MecanicCompany es una solución moderna y profesional que utiliza tecnologías probadas en la industria. Esta estructura asegura que el sistema pueda manejar los requisitos actuales de una empresa de mantenimiento vehicular mientras proporciona flexibilidad para futuras expansiones y mejoras. La separación clara de responsabilidades entre capas facilita que múltiples desarrolladores trabajen en paralelo en diferentes componentes sin interferencias.
